============================================================
  括号看成"山" —— 前缀和的几何直觉
============================================================

一、基本映射
──────────────────────────
  把 '(' 看作 上坡 (+1)，把 ')' 看作 下坡 (-1)。

  前缀和 p[i] = 经过前 i 个字符后的"海拔"。

  例如:  s  =  (  (  )  )  )  (  (
         p  =  0  1  2  1  0 -1  0  1

  画成图:

    ^
  2 |      /\
  1 |    /    \
  0 |  /        \      /\
 -1 |            \  /
    +------------------------>

  整条括号串就是一座山脉的轮廓线。

  所有的 '(' 是上升段，所有的 ')' 是下降段。


二、最长正则括号子序列 (LRBS) 的几何意义
──────────────────────────
  结论：LRBS/2 = total_close + min_p

  其中 total_close = 字符串中 ')' 的总数
        min_p       = 前缀和的最小值（山谷最低点）

  几何理解：
    total_close 是"需要匹配的右括号总数"
    min_p 是山谷最深处的海拔（负数）
    total_close + min_p = 能真正匹配上的对数

  直观解释：
    山的"左半边" '(' 不能全用 —— 必须留一些来填平山谷。
    min_p 的绝对值 |min_p| 就是"被山谷吞掉"、无法匹配的 '(' 数量。


三、一个具体的例子
──────────────────────────
  s = "(()))"

  p:  0, 1, 2, 1, 0, -1

    ^
  2 |  /\
  1 | /  \
  0 |/    \
 -1 |      \
    +-------->

  total_close = 3  (有三个 ')')
  min_p       = -1 (山谷在 -1)
  LRBS/2      = 3 + (-1) = 2
  LRBS        = 4

  原本有 3 个 ')'，但山谷吞掉了 1 个匹配机会，
  所以只能匹配 2 对，LRBS = 4。✓


四、删除操作在几何上的含义
──────────────────────────
  记 R = 山谷最低点的最右位置 (p[R] = min_p)。

  ★ 重要：必须先删左边 '('，再删右边 ')'！

  原因：删左边的 '(' 会改变山谷结构 (R 可能移动)；
       删右边的 ')' 不改变山谷。先修结构问题，再修数量问题。

  删除 R 左边的 '(' :
    → 整个右侧山体下沉一格 (min_p 变得更负，山谷更深)
    → 更深的山谷意味着更多 '(' 被浪费、更少匹配
    → LRBS 减少 2

  删除 R 右边的 ')' :
    → total_close 减少，山体形状不变 (p[R] 不变)
    → 这是"削减右括号总数"，直接减少可匹配的对数
    → LRBS 减少 2

  删除其他地方:
    → 不影响山谷，也不影响关键位置的 total_close
    → LRBS 不变 (浪费了一次删除)


五、一般规律
──────────────────────────
  任何括号字符串 s，删除至多 k 个字符后，
  最小可能代价 = max(0, 原始LRBS - 2*k)。

  能否达到这个下界？能。

  策略（先左后右！）：
    1. 算出前缀和 p[i]，找到 min_p 和 R
    2. 先删 R 左边的 '('（使山谷更深 → 减少匹配）
    3. 还不够再删 R 右边的 ')'（削减右括号总数）
    4. 每一步 LRBS 减 2，直到 0 或删除次数用完


六、这个问题本质
──────────────────────────
  括号问题 → 前缀和 → 山的轮廓 → 山谷决定瓶颈

  这个"把括号看成山"的视角，统一了括号匹配的几乎
  所有问题：最长有效括号、最少添加使括号合法、括号
  染色、括号删除最小化代价……

  核心就是一句话：

    "山有多深 (|min_p|)，就有多少 '(' 被浪费。"
